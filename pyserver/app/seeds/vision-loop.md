# 보고 조정하기 — 이미지 생성 루프와 검수 제안

생성한 그림을 **직접 보고** 고치는 절차다. 보지 않은 그림에 대해서는 아무 말도 하지 않는다 —
view_image / compare_images / review_folder 가 이번 턴에 돌려준 것만이 네가 본 것이다.

## 한 장 루프 (생성 → 보기 → 하나만 바꾸기 → 재생성)

1. **의도 확인**: 무엇을 그리려는지 한 줄로 적는다. 기존 이미지를 따라가려면 `studio_recipe` 로
   프롬프트·시드·모델을 읽는다.
2. **1~2장 생성**: `studio_generate` (spec.scenes 인라인, count 1~2). 완성 장은 대화창에 뜬다.
3. **보기**: `view_image(path, question)` — 질문은 체크리스트로 구체적으로:
   피사체·포즈·표정·손(개수)·눈·의상·배경·잘림·글자/워터마크·레터박스. 한 번에 한 장.
4. **진단 → 변수 하나만**: 문제를 한 문장으로 적고 **한 가지**만 바꾼다 — 태그 추가/삭제,
   가중치({{ }} 는 NAI 강조 문법이니 건드리지 않음), 네거티브 한 항목, 시드, scale, 스텝.
   두 가지를 동시에 바꾸면 무엇이 효과였는지 모른다.
5. **재생성 전에 사용자에게 묻는다**: 본 것·문제·바꿀 한 가지를 말하고 "다시 만들까요?" 라고
   묻고 답을 기다린다. 검수에서 떨어진 그림이 사용자가 원한 그림일 수 있고, 재생성은 Anlas 를 쓴다.
   사용자가 "알아서 고쳐" 처럼 자율 루프를 명시했을 때만 묻지 않고 재생성한다.
6. **재생성 → 비교**: `compare_images("이전, 새것", "무엇이 나아졌고 무엇이 남았나")`.
7. **3라운드에서 멈춘다**: 나아지지 않으면 시도한 것과 남은 문제를 정리해 사용자에게 보고하고
   방향을 묻는다. 비용(Anlas)은 studio_generate 가 매 배치 말해 준다.

## 폴더 검수 (많은 후보 → 제안)

검수 탭의 **AI 재검수** 버튼은 이 절차를 그 폴더에 다시 돌려 달라는 요청이다: 제안만 새로 적고 표시는 바꾸지 않는다.

1. `image_metrics` 로 먼저 거른다: 흐림(선명도 "흐림")·레터박스·근접 중복은 보지 않아도 버릴 후보다.
2. `review_folder(folder, criteria)` — criteria 는 "무엇이 합격인가" 한 문장
   (예: "정면 미소, 얼굴 전체 보임, 손 정상, 잘림 없음"). helper 모드면 장별 판정이 돌아오고,
   메인 모델이 직접 보는 모드면 그림이 첨부된다.
3. 판정을 **제안으로** 적는다: `suggest_selection(folder, [{"file","verdict","reason"}, …])`.
   verdict 는 use(채택) / delete(버림) / inpaint(수정 필요) / none(제안 취소). 이유는 한 문장.
4. `studio_open(folder)` 로 검수 탭을 열어 주고 정확히 이렇게 말한다:
   **"검수 탭에 제안을 적었습니다 — 확인해 주세요."** 결정은 사용자가 한다.
   제안을 근거로 삭제·내보내기·봇 반영을 하지 않는다.

## 거절·불가 분기

- 결과가 **VISION REFUSED** 로 시작하면 그림을 못 본 것이다. 수치만 전하고, 비전 모델이
  거절했다고 말하고, ⚙ → 에이전트 → 비전 툴에서 무검열/로컬 보조 모델(Ollama 의
  qwen2.5-vl 등)로 바꿀 수 있다고 안내한다. 내용을 추측해 채우지 않는다.
- 비전이 꺼져 있거나(`vision is off`) 메인 모델이 확인되지 않았으면(`not verified`) 같은
  방식으로 수치만 쓰고 설정 위치를 안내한다.
- 턴당 호출 한도(`budget`)에 닿으면 남은 후보는 다음 턴에 이어서 본다고 말한다.
