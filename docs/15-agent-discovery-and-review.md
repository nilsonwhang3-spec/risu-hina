# AI 검색·도구 원문·누적 검수

2026-09-14 SSH 운영 로그 확인: 최근 작업 대화에서 `list_assets`가 뒤쪽 이름 전에 잘려
AI가 DB에서 이름/ID를 다시 찾았다. `list_scripts`의 수천 개 항목은 현재 턴 맥락 압축으로
중간이 생략됐고, `recall_work`는 실행 중 도구의 전체 결과를 제공하지 못했다.

DB의 관계형 구조 자체보다 AI 도구의 검색·페이지 이동·저장 상태 설명 부족이 원인이었다.
CHARX 압축 해제본은 파일 검색에 편하지만 정적 카드 원본이다. Hina의 승인 대기, 작업본 수정,
원본과 충돌, 스튜디오 검수 상태를 대신하지 못한다. DB를 파일로 전환하지 않고 다음을 제공한다.

- `bot_structure`: 봇/채팅, 카드 필드, Regex/Lua, 로어북, 에셋 참조와 바이트, AI 대화의 구분.
  동기화된 원본 → 제안 → 승인된 작업본 → RisuAI 반영의 단계와 현재 dirty/충돌/승인 대기 상태.
- `search_bot`: 현재 작업본의 카드 본문·스크립트 JSON·에셋 참조·봇/현재 채팅 로어북을 검색하고
  편집 ID와 본문 읽기 도구를 반환한다. 채팅 내용은 `search_turns`, 파일 내용은 `search_files`.
- `list_scripts(kind="assetref", query=...)`: 수정할 에셋 참조 ID 검색. `list_assets(query=...)`는
  동기화된 참조/바이트 현황이며 둘은 승인된 작업본 변경이 있을 때 다를 수 있다. 둘 다 페이지 지원.
- `read_tool_result`: 길거나 맥락 압축되는 도구 원문을 먼저 저장하고 ref/문자 offset으로 읽는다.
  현재 턴에서도 즉시 사용 가능하다. 스냅샷이므로 최신 검수 상태는 읽기 도구를 다시 호출한다.
  기존 로그에서 이미 잘린 원문을 소급 복원하지는 못한다.

검수 버튼은 use/inpaint/delete 중 하나 또는 미검수이며 AI 제안은 별도다. 클릭마다 원래 폴더에
순서대로 저장한다. 기존 충돌 플래그는 delete > inpaint > use로 해석해 미수정 이미지를 채택하지
않는다. 검수 상태와 그룹 규칙은 원자적으로 기록하고 화면과 `studio_group`이 같은 규칙을 사용한다.
새 후보는 미검수이며 기존 결정은 보존된다. 애셋 채택/selected 내보내기는 상태 조회의 전제가 아니다.

인페인트는 소스 폴더와 슬롯을 유지한다. 추가 생성은 기존 호출 커맨드·구분자·필드 순서·그룹 규칙을
먼저 확인하고 같은 폴더/슬롯에 저장한다. 물리 후보 파일 번호와 등록 에셋 이름을 구분한다.
복수 채택은 동일한 등록 이름의 Risu 기본 랜덤 후보이다. PNG 저장 키 안의 WebP 내용도 유효하다.
CBS의 `{{:else}}`는 단독 줄로 보존한다.

추가/교체 전 프로젝트의 원본 PNG/WebP를 보관하고 원본↔슬롯↔반영 파일 대응을 남긴다.
WebP 변환 여부와 품질/압축률을 사용자에게 먼저 확인하며, 이미 받은 선택은 다시 묻지 않는다.

스튜디오 편집기의 기본값 100 순서 입력은 제거했다. 기존 파일의 순서 메타데이터는 보존한다.
스타일 아래 + 버튼으로 펼치는 임시 프롬프트는 메모리에만 유지하고 생성 spec의 extra에 합친다.
스타일 파일과 로컬 저장 설정에는 쓰지 않으며 새로고침하면 초기화된다. 접어도 입력값은 적용되고,
비우기를 누르면 다음 생성에서 빠진다. 생성 이미지에는 실제 사용한 프롬프트 메타데이터가 남을 수 있다.
임시 네거티브도 독립된 +/비우기 입력을 제공하며 negativeExtra로 전달한다. 단일/배치 계획에서
장면 네거티브와 합쳐져야 하며, 장면 설정으로 임시 입력을 덮어쓰지 않는다.

`realooc` 호환 모듈은 원래 제공되고 있었지만 run_python 본문의 문자열 연결 식은 Python
docstring이 아니어서 헬퍼 설명이 도구 스키마에서 누락됐다. 이제 등록 전에 설명을 명시적으로
설정한다. 두 모듈은 매 실행 전 scripts/에 생성되고 PYTHONPATH가 준비되므로 직접 import하면 된다.

검증: `tests/test_review_discovery.py`, `tests/review_decisions.mjs`, 기존 context/studio/assetrules
회귀 테스트와 TypeScript 검사, 실제 임시 백엔드에 연결한 플러그인 smoke 테스트를 사용한다.

모바일 검수 열기는 중앙 화면으로 전환하고, 후보 화면 위에 전체 그룹 버튼을 고정한다.
모바일 상단 검색은 숨긴다. 명시적인 RisuAI 반영 요청은 어느 탭에서도 플러그인 저장을
실행하고 검증된 완료 결과를 AI에 돌려준다. 연결되지 않은 요청은 만료해 늦은 저장을 막는다.

파일 목록은 단일 scandir 순회와 동시 요청 공유로 갱신한다. 실제 운영 공간에서 기존 스캔은
약 3초, 새 스캔은 약 0.04초였다(네트워크/화면 렌더링 제외). 일시적인 502/503/504는 목록
조회만 재시도하며, 실패해도 이전 트리를 유지하고 알린다. 변경 요청은 중복 실행하지 않는다.
중앙 패널 전체와 왼쪽 트리에서 파일/폴더 드롭을 받고, 파일은 드롭 시점의 File 객체를
우선 사용하여 webview filesystem URL의 EncodingError를 피한다. 왼쪽 폴더도 다중 드래그로
이동할 수 있고, 선택에 부모/자식이 함께 있으면 부모만 이동한다.
