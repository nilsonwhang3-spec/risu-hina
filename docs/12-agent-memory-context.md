# 에이전트 메모리와 작업 맥락 (0.15.1)

설정 → 에이전트에서 메모리와 자동 맥락 압축을 설정한다. 둘 다 기본으로 켜져 있다.

## 메모리

에이전트는 확인한 사용자 선호, 결정, 진행 중인 작업의 핵심 정보를 `remember_note`로 기록하고 `recall_notes`로 검색한다. 기본 저장 범위는 현재 프로젝트다. 모든 프로젝트에 적용하는 사실만 공통 메모리에 저장한다. 설정 화면에서 내용을 직접 추가·수정·삭제할 수 있다.

메모리는 `data/agent-notes`에 저장되어 새 대화와 서버 재시작 후에도 유지된다. 동시 수정은 리비전으로 검사하고 최근 수정 이력 10개를 보관한다. 메모리는 현재 사용자 지시보다 우선하지 않는다. 자격 증명과 전체 대화 원문을 메모하도록 지시하지 않는다. 절차를 재사용하는 스킬과는 별도 기능이다.

## 자동 압축

각 모델 요청 직전에 입력량을 추정한다. 긴 대화뿐 아니라 한 턴에서 툴 호출을 반복할 때도 검사한다. 설정한 컨텍스트 크기에서 출력과 툴 정의에 필요한 공간을 제외하고 여유를 둔다. 기본 컨텍스트 크기는 128,000 토큰이며 모델에 맞게 변경할 수 있다. 토큰 수는 추정치다.

오래된 완료된 툴 교환을 요약하고 사용자 지시 원문과 최근 툴 호출/결과 쌍을 보존한다. 큰 툴 결과는 앞뒤를 남겨 줄인다. 0.15.5부터 요약 실패 시 이전 사용자 지시·답변·요약·툴 교환을 유지하며 발췌 목록으로 대체하지 않는다. 요약이 실패하면 60초간 재시도를 미루며, 실제 입력 한도까지 넘으면 기록을 보존한 채 중단 이유를 알린다. 에이전트가 `compact_context`로 직접 압축을 요청할 수도 있다. 압축과 실패 알림은 답변 안의 한 줄을 갱신하고 최근 기록은 설정에서 확인한다. 실패한 요약도 제공자가 반환한 사용량을 비용 기록에 포함한다. 진단에는 종료 사유, 토큰 수, 텍스트/추론 길이만 기록하며 요약 내용이나 추론 원문을 출력하지 않는다.

## 턴 사이 작업 인계 (0.15.5)

새 사용자 요청에는 같은 대화의 최근 답변, 서버 JOB 상태, 최근 툴 기록, 프로젝트 메모와 저장된 작업 상태가 자동으로 붙는다. `save_work_state`로 목표·완료 보고·남은 일·다음 행동과 근거를 기록할 수 있다. AI의 완료 보고는 실제 완료 증거와 구분한다. 이전 압축에서 사라진 사용자 지시는 DB 원문에서 최근 24,000자 범위까지 복원한다. 더 오래된 기록이나 긴 도구 결과는 `recall_work`의 검색과 페이지 이동으로 조회한다. 사용자 지시 원문 보존량이 누적되어 입력 한도를 넘으면 작업 범위를 나누거나 설정을 확인해야 한다.

인계는 현재 대화 기록의 연속성 기능이며 메모리 설정과 독립적이다. 메모리를 끄면 프로젝트/공통 메모 내용은 전달하지 않는다. 현재 사용자 수정이 이전 기록보다 우선한다.

캐시를 위해 변하는 메모와 인계 데이터를 고정 지침에서 분리해 새 요청에만 추가한다. 정상적인 다음 턴에서는 과거 메시지와 지침의 앞부분을 다시 쓰지 않는다. 실제 압축이나 모델·스킬·설정 변경 시 캐시 적중률은 달라질 수 있으며 서버의 캐시 유지나 과금은 제공자 정책에 따른다.

## JOB 및 파일 화면

0.15.6부터 AI 편집·에셋 제안 승인은 Hina 작업본에 저장한다. 봇 반영을 눌러야 에셋 이미지와 Regex·카드 변경이 함께 RisuAI에 저장된다. 에셋 추가·교체도 즉시 등록하지 않는다. 변경 수는 제안 승인 직후 봇과 챗 모두 갱신하며, 미반영 작업이 있으면 스튜디오·워크스페이스를 포함한 다른 탭에서도 해당 반영 바를 표시한다. 옆의 ⓘ 버튼은 모바일 터치로도 설명을 연다.

PNG와 WebP를 그대로 지원한다. propose_assets_from_folder는 하위 폴더를 포함해 한 제안에 최대 5,000장을 준비한다. 기본 이름은 확장자와 마지막 .2·.3 등의 변형 번호를 제외한 파일명이며, 캐릭터·감정·복장 등 다른 부분은 유지한다. 승인할 때 이미지 사본을 로컬에 저장하므로 원본 파일 이동·삭제와 무관하게 반영할 수 있다. 반영 전 변경 취소는 카드 변경을 버리고 원본 파일은 유지한다.

호스트 saveAsset의 .png 저장 키는 이미지 형식을 보장하지 않는다. WebP 바이트를 변환하지 않고 등록하고 카드에는 webp 형식 정보를 기록한다. 이미지 등록 중 실패하거나 카드 저장 검증에 실패하면 미반영 작업을 유지한다. 구버전 플러그인은 미반영 에셋을 포함한 카드 반영을 차단하므로 백엔드와 플러그인을 함께 0.15.6 이상으로 갱신해야 한다.

AI의 카드 조회는 작업본 조회이며 RisuAI 저장 검증과 다르다. 지침에서도 제안 대기·작업본 저장·RisuAI 반영 완료를 구분한다. 툴 결과 로그는 현재 SDK의 event.part에서 읽어 결과 내용과 호출 ID를 보존한다.

배치 목록은 최근 완료 작업과 모든 실행·대기 JOB을 함께 조회한다. AI는 `studio_job`으로 조회하고 `studio_cancel`로 취소한다. 실행 중 취소는 현재 이미지 처리가 끝난 뒤 적용하며 이미 저장한 이미지는 유지한다.

0.15.4부터 AI 생성은 스타일과 캐릭터를 명시해야 한다. 실제 생성 수가 2장 이상이면 스타일·캐릭터·감정/장면·수량·해상도·참조·저장 위치·예상 비용을 담은 확인 카드에서 승인받은 뒤 JOB을 생성한다. 배열 사양과 인라인 장면도 실제 총 이미지 수로 판단한다. 배치에는 ‘이번 턴 항상 허용’을 적용하지 않는다. 승인한 프롬프트와 장면 확장, 참조 설정을 실행에 사용하므로 확인을 기다리는 동안 활성 카드를 바꿔도 다른 스타일로 실행되지 않는다.

이미지 상세는 원본을 사용하는 공통 모달로 열리고 원본 크기 확대를 지원한다. OUTPUT과 워크스페이스는 파일 클립보드를 공유한다. Ctrl+C 또는 Ctrl+X 후 대상 폴더에서 Ctrl+V로 복사·이동한다. 일부 이동이 실패하면 해당 항목은 클립보드에 남는다.

모바일 검수 카드도 화면상 카드 너비와 기기 픽셀 밀도에 맞춰 768~1536픽셀 썸네일을 요청한다. 원본보다 크게 확대 생성하지 않으며 화면 밖 이미지는 기존처럼 해제한다.
