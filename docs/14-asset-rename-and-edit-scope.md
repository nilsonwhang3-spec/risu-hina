# 에셋 이름 일괄 변경과 편집 모드

AI의 `rename_assets`는 등록된 카드 에셋의 이름을 변경한다. 출력 파일명의
규칙을 다루는 `studio_naming`과 다르다. 기존 안내가 Regex 편집 도구를
에셋 변경에도 쓰도록 설명했고 `list_scripts("assetref")`는 이름 대신
‘설명 없음’을 나열했다. 최근 로그에서는 이 때문에 AI가 서버 소스와 내부
HTTP 경로를 run_python으로 반복 탐색했다. 이름 목록과 안내, 전용 도구를 수정했다.

예: `find="__", replace="-", preview=True`로 건수와 변경 전후 예시를 확인한다.
대상을 설명하고 `preview=False`로 제안하면 한 번의 승인으로 작업본에 반영한다.
`name_filter`는 대상 이름을 고르는 정규식이며 `field`는 additional/emotion/cc/all이다.
`regex=True`는 Python 치환식이다. 서로 다른 이름이 합쳐지는 경우에는 미리보기에서
충돌을 표시하며, 의도한 랜덤 풀인 경우에만 `allow_merge=True`를 사용한다.
원래 같은 이름인 변형은 그대로 유지한다. `.2`, `.3` 등을 자동 변경하지 않는다.

승인 시 미리보기의 에셋 목록과 현재 목록을 비교한다. 목록이 달라지면 전체 변경을
중단한다. 이름만 바꾸므로 이미지 키·확장자·순서·원본은 유지되고 재업로드하지 않는다.
실제 RisuAI 등록 이름에는 별도의 ‘봇 반영’이 필요하다. Regex/노트의 사용처는
사용자가 요청한 범위에서 별도 확인한다.

봇/챗 편집 모드는 각각 해당 자료의 변경만 제안·승인한다. 로어북처럼 scope에 따라
대상이 달라지는 도구도 검사한다. 모드 변경 후 예전 제안을 승인할 때 다시 검사하며,
Python의 챗 수정 제안 수집도 챗 편집 모드로 제한한다. 작업 중 읽기·분석은 가능하다.
공용 탭의 반영 도구는 현재 편집 모드에 맞게 표시한다. 스튜디오의 에셋 채택은 유지한다.

반영 중에는 Hina 배경 요소를 inert로 전환하고 클릭·터치·스크롤·키보드·드래그 입력을
차단한다. 성공/실패 후 기존 inert와 overflow 상태를 복구한다. Hina 뒤의 호스트 UI를
별도 조작하거나 mainDom 권한을 요청하지 않는다.

신규 설치 기본값: 모델 컨텍스트 창 220,000토큰, 턴당 도구 호출 60회.
대화 예산은 컨텍스트 창의 80%에서 지침·도구 정의·최대 출력 토큰을 뺀 만큼 자동 계산한다.
압축 시작, 보존할 대화량, 압축 기록은 추정 토큰 기준이다. 별도 글자 수 제한은 없다.
기존 `historyBudgetChars` 값은 파일에 남아 있어도 무시한다. 사용자 지정 컨텍스트 창은 유지한다.
