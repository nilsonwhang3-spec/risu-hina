# 0.15.7 반영 진행 표시와 에셋 처리

봇/대화 반영은 전면 스피너로 진행 상태를 표시한다. 에셋은 완료 개수,
카드 저장·검증, 작업본 동기화 단계를 구분한다. 백업 후 반영과 봇 복제도
같은 표시를 사용한다. 반영 작업이 진행되는 동안 중복 반영은 거부한다.

기존 에셋 반영은 각 파일의 Hina blob 다운로드, RisuAI saveAsset,
Hina adopt 기록을 모두 순차 실행했다. 0.15.7은 첫 파일을 먼저 저장하여
웹 RisuAI AutoStorage.Init 초기화를 끝낸 후, 최대 4개 파일을 동시에 처리한다.
한 번에 모든 파일을 메모리에 읽지 않는다. 중복 pending 키는 한 번만 처리하고,
완료 순서와 무관하게 카드의 에셋 배열 순서와 이름, 변형 이름, 확장자 메타데이터를 유지한다.

확인한 호스트 소스:

- RisuAI `src/ts/globalApi.svelte.ts` saveAsset → AutoStorage.setItem.
  웹 저장소는 LocalForage/OPFS, NodeStorage 또는 AccountStorage로 분기한다.
- PocketRisu의 동일 API → AutoStorage → NodeStorage의 파일별 `/api/write`.
- 두 호스트의 플러그인 API는 파일별 saveAsset을 노출한다.
  Hina는 공통 API를 유지하며 호스트 전용 저장소나 비공개 일괄 API를 직접 호출하지 않는다.

처리 중 하나가 실패하면 새 파일을 시작하지 않고 이미 시작한 저장을 기다린다.
카드 쓰기는 실행하지 않으며 미반영 작업본을 보존한다. 이미 저장된 파일은
호스트 저장소에 남을 수 있으며, 재시도 시 재전송할 수 있다.

검증: 1,301개 작업의 동시 실행 상한·초기화 순서, 중간 실패 후 종료 대기,
중복 반영 차단, 실제 Hina 백엔드와 모의 호스트를 연결한 DOM 반영/재시도 테스트.
이 테스트는 실제 웹/PocketRisu 기기에서의 성능 측정이 아니다. 실제 개선 폭은
이미지 크기, 브라우저 저장소, 서버 및 네트워크에 따라 달라진다.
