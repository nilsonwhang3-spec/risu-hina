# 프로젝트 에셋 규칙

에셋스튜디오 검수 화면의 **에셋 규칙**에서 프로젝트 폴더명을 지정하고,
여러 명명 규칙과 에셋 세트를 저장한다. 요청 설정에서도 같은 편집기를 열 수 있다.

## 명명 규칙과 세트

- 명명 규칙: `{character}-{emotion}` 또는
  `{character}_{emotion}_{outfit}_{variant}` 같은 템플릿, 확장자,
  필드별 허용값과 빈 값 대체어를 정의한다.
- 에셋 세트: 명명 규칙 하나와 슬롯 목록을 연결한다. 각 슬롯은 character를
  제외한 필드값과 필수·선택·제외 상태를 가진다.
- 적용 캐릭터 목록을 비우면 전체에 적용한다. 캐릭터별 예외 상태가 슬롯의
  기본 상태보다 우선하며, 세트의 적용 대상에서 빠진 캐릭터는 제외한다.
- 규칙과 세트 ID는 저장 후 참조에 사용한다. 이름은 표시용이다. 슬롯 ID를
  변경하면 해당 ID를 쓰던 예외 설정과 기존 이미지의 연결도 명시적으로 정리해야 한다.

**필수** 슬롯만 부족분으로 계산한다. **선택** 슬롯은 없어도 완료로 인정하며,
**제외** 슬롯은 생성·내보내기·봇 반영 대상에서 거절한다. 동일 슬롯의 후보가
여러 장이어도 충족한 슬롯은 하나이다. 부족분은 선택한 폴더와 하위 폴더의 현재
채택 상태를 읽으며, 예전 selected/ 내보내기 사본으로 채택 여부를 추측하지 않는다.

## 후보 번호와 봇 이름

같은 에셋을 여러 장 채택할 수 있다. 저장 파일은 `A-happy.webp`,
`A-happy.2.webp`, `A-happy.3.webp`처럼 번호를 붙이고, RisuAI에는 모두
`A-happy`라는 이름으로 추가한다. 번호는 파일 보관용이며 그룹·슬롯 필드가 아니다.
별도 변형 슬롯을 만들 필요가 없다. 명명 규칙의 regex는 이 번호를 비캡처로 처리한다.

생성 후보는 PNG로 저장하며, 동일 이름은 `.2.png`, `.3.png`로 보존한다.
선택한 확장자로의 변환은 내보낼 때 수행한다. 봇 반영은 기존 호스트 API에 맞는
PNG 사본을 준비한 뒤 같은 논리적 이름을 전달한다.

규칙은 번호 캡처를 제외한 일반 캡처 그룹을 사용하며, 그룹 순서는 템플릿 필드
순서와 같다. 구분자가 필드값에도 들어가 필드를 다르게 읽게 되면 저장/생성 전
오류로 알린다. 허용값을 지정해 모호함을 해소하거나 다른 구분자를 선택할 수 있다.

## 생성과 기존 파일

요청 설정에서 프로젝트·세트·슬롯을 선택한다. 슬롯을 `씬 이름으로 결정`으로
두면 슬롯의 emotion 값과 씬 이름이 정확히 하나 맞아야 한다. 다른 필드 체계를
쓰거나 같은 감정에 여러 슬롯이 있으면 슬롯을 명시한다.

AI는 `studio_asset_rules`로 규칙을 읽고, 생성 spec 또는 각 entries 원소에 다음을 넣는다.

```json
{
  "asset": {
    "project": "Example Project",
    "setId": "expressions",
    "slotId": "happy",
    "fields": {"character": "A"}
  }
}
```

이미지에는 규칙 스냅샷·필드값·이미지 ID를 기록한다. 인페인트는 이를 계승하고
새 이미지 ID와 원본 ID를 기록한다. 그룹은 이 정보로 결정하므로 후보 번호나
파일명 변경에 영향을 받지 않는다. PNG에 정보를 내장하며, 기존 파일의 명시적
규칙 지정과 WebP/JPEG 출력은 경로 및 내용 해시로 연결 정보를 별도로 관리한다.
동일 바이트를 서로 다른 슬롯에 지정한 경우 경로별 지정을 우선하고, 새 경로에서
해시만으로 어느 슬롯인지 추측하지 않는다.

기존 이미지의 **규칙** 버튼에서 파일명으로 가능한 세트를 찾고 명시적으로 적용한다.
여러 세트가 맞으면 선택지를 모두 표시한다. 규칙을 지정하지 않은 기존 폴더에는
종전 파일명 파싱·내보내기가 유지된다. 관리 대상과 미지정 파일을 함께 채택하면
미지정 파일을 먼저 연결해야 한다.

내보내기 미리보기는 원본 경로·최종 파일명·봇 에셋 이름을 반환한다. 서로 다른
의미의 규칙이 동일한 이름을 만드는 충돌은 별도로 표시한다. 변환을 모두 마친 뒤
selected/를 교체하고, 직전 내보내기는 `.selected-backup-…` 폴더로 남긴다.

## API와 검증

- `GET/POST /studio/asset-rules`: 프로젝트 규칙 읽기/저장. revision으로 동시 편집을 확인한다.
- `POST /studio/asset-match`: 파일명의 모든 일치 후보 조회.
- `POST /studio/asset-bind`: 이미지에 세트·슬롯 지정.
- `POST /studio/asset-coverage`: 캐릭터별 채택 슬롯과 부족분 집계.
- `POST /studio/export`의 `preview: true`: 저장 전 파일명 매핑 확인.

`tests/test_assetrules.py`는 실제 임시 파일로 번호·그룹·인페인트 계승·확장자 변환·
이름 변경·동일 바이트의 다른 슬롯·실패 시 기존 내보내기 보존을 확인한다.
`tests/plugin_smoke.mjs`는 실제 백엔드에 연결해 화면에서 규칙·세트·슬롯 저장을 확인한다.

## 0.15.0 저장·학습·복구

새 생성은 `studio/output/<프로젝트 폴더명>/`에 저장한다. 봇의 고정 프로젝트 폴더명을
사용하며, 명시한 하위 폴더는 그 아래에 유지한다. 프로젝트가 전혀 없는 요청만
`studio/output/_unassigned/`로 보낸다. 기존 이미지의 일괄 이동은 하지 않는다.
인페인트도 원본 프로젝트와 에셋 정보를 계승한다.

AI는 검증한 절차나 사용자 수정 근거를 `improve_skill`로 저장한다. 기존 스킬은
현재 revision이 일치해야 수정할 수 있고, 사용자의 활성화·항상 적용 설정을 유지한다.
설정 → 스킬 → 수정 → 변경 기록에서 이전 본문과 근거를 확인하고 되돌릴 수 있다.
프로젝트 한정 절차는 본문에 적용 조건을 명시하며, 근거·세션·프로젝트를 함께 기록한다.

도구 시작·반환과 생성 작업 ID는 대화별 체크포인트로 즉시 저장한다. `work_status`는
최근 체크포인트·작업 상태·남은 검수 한도를 보여 준다. 중단된 턴의 실제 도구 결과를
대화 기록에 유지하고, 결과를 확인하지 못한 호출은 unknown으로 남긴다. 재시작 시
이전 실행의 작업을 중단 상태로 정리하며 자동으로 유료 생성을 반복하지 않는다.
검수의 `offset`/`nextOffset`으로 이어서 읽고, 불완전한 helper 응답은 미검수로 표시한다.

스테이징의 기본 카드 원본은 `app/studio_defaults/manifest.json`의 해시로 검증한다.
3개 스타일, MASTER 16 프리셋, 참조 조각과 랜덤 조각 총 23개를 포함한다.
의상·배경은 제외했고, 사용자 편집본은 설치 시 보존한다. 이 작업에서 성적 생성용
태그를 새로 작성하거나 최적화하지는 않았다. Codex Subscription은 legacy
`OPENAI_CODEX` 값과 관계없이 기본 제공하며 실제 사용에는 구독 로그인이 필요하다.
